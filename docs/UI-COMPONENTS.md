# UI components

Everything reusable lives in `src/shared.tsx`. Usage counts are from the app
files (`ArabicTrainer.tsx`, `spaces.tsx` and `card-editor.tsx`) at the time of
writing — they show
how established each piece is, not how important it is.

**There is a live version of this list.** Admin → App → Components renders
every component below with its variants, labelled, and folds the places it is
used under each one — file, enclosing component and line. It is built from the
real components and from a scan of the source, so it cannot drift the way this
file can — when the two disagree, believe the gallery and fix this file.

The counts below are the ones written when each entry was added, and they age.
`src/component-uses.js` is generated by `npm run components` and is the current
answer; a test re-runs the scan and fails if it has fallen behind the source.

**When asking for UI changes, the useful shorthand is the component name.**
"Put it in a Section with a Help under it" is unambiguous; "add a heading and
some grey text" is not.

**Rule of thumb: if something here fits, use it rather than raw markup.** Two
implementations of one thing is the failure mode this library exists to
prevent — it is how the student's card tile and the teacher's came to show
different information from the same data.

## Layout and frames

### `Screen` — 22 uses
The one full-screen shell. Portals into `.at`, owns Escape (only the topmost
open screen responds), and holds the page under it still while open (see
`usePageLock`). Every full-screen
flow goes through this: there is no second way to make one.

```jsx
<Screen title="Edit card" onBack={close} action={<Button>Save</Button>} footer={<>…</>}>
```
`title, onBack, action, footer, backLabel="Back", children`

`footer` is a sticky bar at the bottom — use it for the primary action of a
form rather than putting buttons in the flow.

### `SpaceFrame` — 2 uses
The Teaching, Admin and Super admin shells. Full-bleed screen, pending
dialog, error line, the tab's title, contents; its tab strip goes to the bar
at the foot of the window (`Tabs` with `dock`).

`tabs, tab, onTab, error, busy, label="Section", dialog, space, children`

### `TabTitle` and `PlaceContext`
`TabTitle` heads a tab with its name, held at the top as the page scrolls.
At its right it shows whatever `PlaceContext` holds: the app's "where you
are" button (0.601), which names the place, the mode and the languages and
opens the sheet that changes them. The app provides it; nothing else
should. Outside the app (the gallery) the context is empty and the title
stands alone.

### `Section` — 7 uses
A titled block. Replaces the hand-built eyebrow-plus-lede opener.

`title, count, lede, action, children, className`

### `Tabs`
`tabs` is an array of `[key, label, iconName]`. Handles `role="tab"`,
`aria-selected` and `aria-current` so you don't have to.

`tabs, value, onChange, label="Section", dots, counts, dock`

With `dock` the strip goes to the bar at the foot of the window (a space's
sections). Without it, it is the one full-width track every page's tabs
share (0.685): equal parts, an icon over each name, the current one raised.
`counts` puts a number under a tab's name, only where it helps choose
(the sentence review). Anything that changes what a page lists is `Tabs`;
`Segmented` is for a setting.

## Text

Each has one job. Reaching for the wrong one is how `at-hint` ended up doing
eight jobs and became impossible to restyle.

| Component | Use for | Uses |
|---|---|---|
| `Lede` | the intro paragraph under a title | 8 |
| `Help` | helper text under a control | 94 |
| `Meta` | small print beside content | 0 |
| `Notice` | errors, warnings, success, busy | 16 |

`Notice` takes `kind="info" | "error" | "warn" | "ok" | "busy"` and renders
nothing when its children are empty — so `<Notice kind="error">{error}</Notice>`
is safe to leave in the tree unconditionally.

`Meta` is unused. It exists for count lines that mostly became `plural()`
instead; treat it as available rather than established.

## Controls

### `Button` — 98 uses
`variant="default" | "primary" | "ghost" | "danger"`, `size="sm"`, `wide`,
`icon="add"`, `iconSize`, plus anything a `<button>` takes.

Pass `icon` rather than an `<Icon>` child — that way the spacing is consistent.

The words are boxed in `.at-btnlabel`, which is `display: contents` and so
invisible to the layout — except in an `.at-row` or a screen's footer, where
a label longer than the whole row is wide wraps inside its button instead of
running off the side of the screen. A raw `<button className="at-btn">` has
no box and does not get that; use `Button`.

### `IconButton` — 15 uses
An icon-only button. `label` is **required** and becomes the accessible name.

`icon, label, danger, ghost, className, ...rest`

`ghost` is the same outline-without-fill as `Button`'s ghost variant. Use it
when the icon stands in a row beside ghost `Button`s — the hint button next
to "I don't know" — so the two read as the same weight.

### `SearchBox` — 6 uses
A search field. Once something is typed, a cross at its right end empties it
and leaves the cursor in the box. Every box that narrows a list is one of
these — ItemList's search included — so they all clear the same way. The
browser's own clear button is hidden so there is only ever one cross.

`value, onChange(next), className` (on the input), `boxClassName` (on the
wrapper), `style`, plus anything an `<input>` takes.

### `Segmented`
Pick one from a few: a setting, or a filter. Reports `aria-pressed`. Not for
switching between views of a page — that is `Tabs`.

```jsx
<Segmented
  options={[{ value: "off", label: "Off" }, { value: "on", label: "On" }]}
  value={current} onChange={set} label="Grouping"
/>
```
`options, value, onChange, size="sm", label, disabled`

Options may be `{value, label}` or bare values. `size={null}` gives full-size
buttons. For **multi-select**, this is the wrong component — use `CheckList`,
or `Button`s with `aria-pressed` in a `.at-segmented` wrapper.

### `Field` / `FormField` — 20 + 28 uses
A labelled control. Same component: `spaces.tsx` imports it as `Field`, the
trainer as `FormField` (it has its own unrelated `Field`).

`label, hint, optional, htmlFor, children, className`

### `CheckList` — 4 uses
Pick several. `options, chosen, onToggle, empty`

`chosen` is an array of ids, and `onToggle` is called `(id, wasOn)` — the
second argument saves the caller working out which way the tick just went.

### `MoreMenu` — 3 uses
Three dots that open the app's one context menu (0.689; a sheet since
0.690): the less used things done with a tile or a list — a module's Export
and Delete, a list's Import — out of the way of the one it is for.
`label, title, lede, items, ghost=true`

The panel is a `PickSheet` of `SheetAction` rows, the same one a saved
session's dots open on Focused training: up from the foot of a phone, in the
middle of a wide screen, headed by `title`. **Any new menu of actions on a
thing is one of these**, not a list hanging from a button. `items` is
`[{ label, icon, danger, note, disabled, onClick }]`; anything falsy is left
out, so an action only some things have is written in place with `&&`. Its
clicks stop at it, so a tile it sits on does not open as well.

### `SheetAction`
One row of that panel: its icon in a round well, its name, and a line under
it where it cannot be done and why. `icon, label, note, danger, disabled,
on, onClick`

`on` marks the choice that holds now, edged and ticked, where the panel
chooses one of a few rather than acting (0.691): a card's status
(`StatusMenu`) and `FilterMenu` open the same `PickSheet` of these rows.

### `FilterBar` / `narrowing(groups)` — 3 uses
The pickers a list's Sort or Filter panel holds. `groups, note, onClear`

A group is `{ key, label, value, quiet, onChange, options }` and draws a
`Segmented`; `quiet` names the value that counts as not narrowing, and
`narrowing(groups)` counts the ones that are away from it — that count is
what the Filter button carries. A group with `custom` draws that instead, for
a choice a row of buttons cannot say (which decks, of all of them), and `wide`
gives it a line of its own. `chip` is what the group's chip under a list's bar
says while it narrows ("Without recordings"; its `label` otherwise), and
`onReset` puts that one group back — the chip's cross.

It is only the pickers: the button, the panel they open in and the chips
belong to `ItemList`'s `filter` (0.727). The Sort panel builds its own two
groups from `ItemList`'s `sort`.

### `RadioGroup` — 2 uses
One of a few, as a list of rows rather than a track of segments.

`options, value, onChange, label, name`

Each option is `{ value, label, note? }`, and the note is the line under the
label saying what the answer gets you. Reach for this over `Segmented` the
moment an option needs explaining — a segment holds two or three words and
nothing else. Built from the same `at-tickrow` furniture as `CheckList`, with
`type="radio"` doing the exclusivity, so it needs no styling of its own.

### `LanguageRadio` — 4 uses
The languages, through `RadioGroup`. `languages, value, onChange, label, name`

## Lists and tiles

### `ItemList` — 9 uses
The standard list frame: one bar of controls, a quiet line under it, the
list, a slim bar at the foot while selecting, empty state, and paging at 120
items.

`noun, plural, items, itemKey, match, groups, groupOf, size="large"|"small",
views, onNew, newOff, renderItem, selected, onSelectedChange, bulkActions,
tools, more, narrow, sort, filter, total, filters, query, empty, emptyPanel,
busy`

**The bar is one row** (0.727): New (+ alone under 640px, "+ New card"
from there), the search box taking what is left, Filter (with the count of
filters on, and its word from 640px), `narrow`, and three dots. The dots hold
Select first, where there is anything to select, then `more` (Import, where a
list has it); where Select would be alone in them it is an icon of its own
and there are no dots. `tools`, the screen's worded button ("Manage this
deck's cards"), is on a row of its own above the bar. Each part is left out
when it would hold nothing, and with `emptyPanel` showing the bar stands
aside.

**The quiet line** under the bar, in small muted type: the count ("14 cards",
or "5 of 14" while narrowed, against `total`), Clear while a filter is on,
and at the end the order (opening the Sort panel) and the view switch. It is
drawn only where it says more than a count — a list with `sort` or `views`,
or narrowed, or selecting — so People has none. Under it, while filtered,
each filter in force is a chip on one line that scrolls sideways.

`sort` is `{ value, down, options, onApply(value, down) }`, each option
`{ value, label, down, up, saysDown, saysUp }`: `label` is its name in the
panel, `down`/`up` its two directions there, `saysDown`/`saysUp` what the
line reads. **The Sort panel keeps a draft and waits for Apply**; shut any
other way it changes nothing. `filter` is `{ groups, onClear }` — `FilterBar`
groups, which **take hold as they are ticked**; the panel's button reads
"Show 5 cards" and only shuts it. One panel at a time, from the foot of the
screen (`PickSheet`), its contents scrolling above a button that stays put.

**Selecting** starts from Select, or from a finger held on a tile or table
row (touch and pen, 500ms, cancelled by 10px of movement; the click after is
swallowed). While it lasts the search box and Filter stay, New and the dots
give way to a cross ("Done selecting"), and the line reads "3 selected" with
Select all. The foot bar says how many and has one **Actions** button, which
opens a panel of `bulkActions` as rows, each with its `icon`, `danger` ones
last. It is still fixed to the foot and measured into `--bulk-h`, which the
list reserves at its end.

`views` adds the view switch — grid or table. It is
`{ key, columns, row(item) }`: `row` gives a card's `cells` by column key for
the table, and the `open` and `actions` a tile would have. `key` names the
list, and each list keeps the view it was left at on the device.
`cardWords`, `cardKindLabel` and `cardSubtypeLabel` say a card's words, kind
and subtype the same way in every list.

`match` is `(item, lowercasedQuery) => boolean`. `bulkActions` is
`[{ label, icon, danger, onClick(ids) }]`, and **`ids` is an array, not the
Set the list keeps internally** — every caller reaches for `.includes` or
`.length`. Give every action an icon of its own; `folder` is drawn where one
is missing.

`itemKey` defaults to reading `.id`, so items need one unless you pass your
own.

`groups` is `[{ key, label }]` and `groupOf` is `(item) => key`. Together they
split the list into labelled runs, each headed with how many are in it
altogether rather than how many the page has reached. **The list is sorted
into the order `groups` gives before it is paged**, so a run is never left
half off the end of a page — which is why the order is the one somebody needs
to read, not the one with the most in it. A run whose key nothing answers with
is not drawn, and where only one run turns out to have anything in it the
headings are left off, because a heading that names the whole list says
nothing. The Progress tab uses it to sort a level's cards into paused,
learning and not started.

### `CardTile` — 2 uses
One card tile for both the learner's and the teacher's lists.

`card, lang, showLat, meta, actions, onClick, className`

`meta` is the one line of small print, and the caller decides what it says.
It replaced a `moduleTitles` prop, which this file and the gallery both went
on advertising for a while afterwards.

A card carrying a `name` is listed under it: the name is the headline, drawn
in the interface face rather than the taught script's, and it stands in for
the meaning line rather than sitting above it. The script keeps its own line
underneath. Nothing is passed for this — the tile reads it off the card —
and only a verb whose own word is a cell of its table has one.

### `Tile` — 7 uses
The generic deck/course tile. `title, meta, onOpen, actions, footer`

Lived in `spaces.tsx` until recently, which made this file wrong about where
reusable things are; it is in `shared.tsx` with the rest now.

### `TileNote` — 4 uses
The line under a tile: whether anyone can see it. `live, children`

### `CardReadout` — 4 uses
Everything a saved card holds, read-only: its kind, its forms, its tables,
its blanks, what other cards call it and where it lives. What it draws is
described once in `src/card-facts.ts`, and a field that list does not name
yet is still shown, raw, at the foot — so the screen cannot fall behind the
editor. `card, lang, decks, cards, reader`

`cards` is the rest of the collection, where the caller has it: what is
behind a blank and how many cards wear a tag are facts about the collection.
`reader` is `"teacher"` (the default) or `"both"` — a student's screen is the
card itself, without which decks carry it or which of its forms are lent.

## Dialogs

### `PersonActions` — spaces.tsx
One person's actions on a People list (0.580): a new sign-in key,
suspending or reactivating, and removing from a space, in Admin's words.
`org` names the space where Super admin acts in one; anything only one screen
offers goes in as children.

### `ReportList` — spaces.tsx
Learners' reports about cards (0.580): `ItemList` with search, Copy and Clear
for what is ticked, and Open card, Copy and Clear on each. Admin's Reports tab
and Super admin's Reports, a list per space.

### `usePicture(hash)` — the hook
A stored picture's data URL, fetched once a session for every screen — see
`src/pictures.ts`. The card editor's pictures and the space's badge use it.

### `ConfirmModal` — 10 uses
`title, body, confirmLabel, confirmWord, busy, danger=true, onCancel, onConfirm`

`confirmWord` makes the person type a word before the button enables — for
things that can't be undone.

Prefer this over `window.confirm`. The one remaining `window.confirm` is the
import gate, which genuinely wants a blocking browser dialog.

### `useRun(options)` — the hook
A screen's one way to do something that may fail (0.580): `{ run, busy,
setBusy, error, setError, clearError }`. `run(work, done)` sets busy, runs
the work, says `done` (a string, or a function of what the work returned)
and puts any failure in `error`. Options: `refresh` after it worked,
`snackErrors` to say a failure aloud too, `quietDone`, and `before` /
`instead` for Teaching's locked-deck note. Admin, Teaching, Super admin's
Spaces and Everyone use it.

### `useConfirm(run, { busy, after })` — spaces.tsx
The question asked before something is done, and its dialog: `{ setConfirm,
modal }`. Yes runs the action through `run` and closes once that worked.
Teaching's dialogs are of several kinds with their own wording and keep their
own.

### `usePageLock(on = true)` — the hook
Holds the page under a layer still while the layer is up. `Screen`,
`ConfirmModal` and `PickSheet` already hold it; anything else drawn over
the whole page — a sheet of its own, an overlay — calls it too. Counted, so
layers can stack. Without it the page behind goes on scrolling, and its
scroll bar is the one in view.

### `Popover` — the menu that drops from a button
`className, children, onClose`, plus anything a `<div>` takes.

`onClose` is how it is left: any click once it is open, its own included,
calls it. Five menus wrote that listener out by hand until 0.580; a menu that
must stay open while it is ticked (the corner menu) stops its clicks from
reaching the page, as before.

Every menu that hangs off a button is one: the filter menus, a card's
status, the corner menu, the space and language menu, a blank's values. Its class
still says where it hangs and how it looks; `Popover` measures it once it
is drawn and moves it back inside the window if it crosses either side,
and cuts it to the room below it, scrolling, if it runs off the foot — or
to the room above, for one that opens upward off the bar at the foot of
the window. A
new drop-down is a `Popover` — never a bare `<div>` with `position:
absolute`, which is how the status menu came to open off the screen.

## Audio

### `useClipPlayer(load)` — the hook
Owns the `Audio` element, the object URL, and the loading/playing/missing
states. Revokes its URL on unmount. Use this rather than a new `Audio()`:
leaking one object URL per clip is a bug this hook exists to prevent.

### `PlayButton` — 0 direct uses (used inside `ClipList`)
`state, onClick, className, label`

### `ClipList` — 2 uses
A list of recordings with playback. `clips, onChange, load`

A clip is a bare hash or `{ id, label }`; both are stored. `load` is
optional — a read-only list, like the one in `CardReadout`, passes none and
its play buttons resolve to "missing" rather than fetching.

## Odds and ends

- **`Icon`** — 22 uses. `name, size=20`. Available names: `add, search, close,
  delete, edit, tune, sort, size, check, back, save, folder, cards, person,
  group, key, download, verify, play, pause, view, select, school, copy,
  refresh, mic, remove, chevronDown, chevronUp, soundOff, flag, menu, help,
  theme, language, lock`.
  Use these rather than glyph characters.
- **`plural(n, noun)`** — `plural(3, "card")` → `"3 cards"`. Use it instead of
  writing `${n} card${n === 1 ? "" : "s"}`.
- **`localIdFor(cardId)` / `serverCardId(item)`** — a card has two names,
  the server's and the device's, and these are the two directions between
  them. Anything sent back to the server uses `serverCardId`; taking the
  prefix off by hand is wrong, because a form of a card is not the card and
  an item that was never course material has no server name at all.
- **`FLAG_KINDS` / `flagTitle(kind)` / `FLAG_NOTE_MAX`** — the four things a
  learner can say about a question — three complaints, and "too easy",
  which moves the form up its ladder on the device and is never sent —
  each with a `title` and the `what` line under it. The trainer renders the list; Admin → Reports names
  what came back with `flagTitle`. Not components, but they live here for
  the same reason: two copies would be two vocabularies for one thing.
- **`languageName(languages, id)`** / **`LanguageTag`** — one place that knows
  how to name a language, including the "not set" case.
- **`useLiveRefresh(fn, everyMs = 45000)`** — refresh on focus, on visibility
  change, and on an interval.
- **`ModeSelector`** — 0 uses. Present and working, but nothing calls it.
- **`SpaceFrame`, `Empty`, `Stat`** are established but lightly used, so
  their APIs are the most likely to need a prop adding.

## Styling

`src/index.css` holds everything, with design tokens at the top.

- **Spacing:** `--s1: 4px` · `--s2: 6` · `--s3: 10` · `--s4: 14` · `--s5: 18` ·
  `--s6: 24`. Utilities `at-mt1`…`at-mt6`, `at-mb2`, `at-mb3`.
- **Don't write inline margins.** Containers already zero the margins of their
  first and last children, so `marginTop: 0` is almost never needed. The 32
  inline styles that remain are dynamic values (computed colours, a font stack
  from the language pack).
- Type scale is `--fs-xs` … `--fs-xl`; z-index layers are `--z-*`. Most sizes
  are written out in pixels rather than taken from a token, so **Text styles**
  in Admin → App is the list to read before setting one: every style the app
  is written in, drawn at its real size with the size it resolves to measured
  off the specimen. `src/text-styles.ts` is the list behind it, and
  `tests/text-styles.test.mjs` fails if a size there and the stylesheet have
  come apart.
- Every `at-` and `ob-` class a stylesheet styles is referenced by something,
  and `tests/css-usage.test.mjs` fails the build when one is not (0.580). If
  you delete markup, delete its CSS — and note that a multi-selector rule is
  only dead if *every* selector in it is. A class put together in code
  (`at-cardtable-${key}`) is listed in the test, with where it is made.

## Keeping this accurate

The gallery in Admin → App is the copy that cannot go stale: it calls the real
components with real props, and the smoke test renders the whole of it, so a
prop that changes shape without the gallery changing with it fails the build
rather than quietly misinforming someone. Add a row there for anything new.

Its usage lists come from `npm run components`, which reads the source and
writes `src/component-uses.js`. Run it after moving or renaming a component;
`npm test` fails while that file is behind, so it will not be forgotten
silently.

This file still drifts the moment components change. When we add, rename or
remove one, update it in the same change — and if it's in the Project knowledge,
re-upload it. A stale list is worse than none, because it will confidently
point at something that no longer exists.
